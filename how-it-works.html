FROM RESPONSE TO READABLE TEXT

How it works?

Follow the journey from Firecrawl’s response to cleaner text, with sources and processing details kept separately for review.

EnglishEspañol

  1. Capture the page

    By default, the URL is sent to Firecrawl once with onlyMainContent enabled and your selected filters and format. Enable original response to make a second request in Markdown with onlyMainContent disabled and no tag filters.

  2. Read the response

    The app takes the requested Markdown or summary from the response and reads the available metadata. Markdown is parsed into blocks such as headings, paragraphs, lists, tables and code.

  3. Organize the content

    The page type determines the output: article text or a collection of captured article cards. Auto-detection recognizes Medium category URLs. Rules for supported sites separate interface elements and supplementary sections; other sites use a generic extraction.

  4. Build readable text

    With local cleanup enabled, Markdown formatting is converted to plain text, link labels are kept, and image markup and citation markers are removed from the narration. Tables become text rows. Code blocks are kept unless you enable “Skip code blocks”. With cleanup off, the configured API text is displayed as received.

  5. Keep context for review

    Links, available metadata, supplementary sections, captions and an omission log are stored separately from the narration. Missing metadata is not invented. You can inspect the structured details and save the original API responses and processed files locally.

  6. Compare the result

    The first column shows the configured API text. The second shows local processing of that same capture; with cleanup off, these two columns are identical. When original response is enabled, a third column shows the independent unfiltered Markdown capture. Collection coverage compares the two captures when both contain full Markdown.

Less text does not always mean better text

A Firecrawl summary changes content, not just formatting. Tokens are estimated as characters / 4; noise matches are not a quality score. The first two columns share a capture. The optional original response is independent and may differ between requests. Site rules are heuristic: review warnings, sources and omissions.
